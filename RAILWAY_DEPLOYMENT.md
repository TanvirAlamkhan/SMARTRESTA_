# SMARTRESTA — Railway Production Deployment Guide

This guide details the steps to deploy SMARTRESTA to Railway.app with Railway MySQL.

---

## 1. Prerequisites
- Railway account & Railway CLI
- GitHub repository with SMARTRESTA source code
- Provisioned Railway MySQL database plugin

---

## 2. Environment Variables in Railway

Add the following environment variables in your Railway Project Settings:

| Variable | Recommended Value | Description |
| :--- | :--- | :--- |
| `APP_ENV` | `production` | Production environment mode |
| `APP_DEBUG` | `false` | Disables verbose debug stack traces for security |
| `APP_URL` | `https://${RAILWAY_STATIC_URL}` | Domain URL generated by Railway |
| `APP_TIMEZONE` | `Asia/Dhaka` | Default restaurant timezone |
| `SESSION_SECURE` | `true` | Enforces HTTPS session cookies |
| `DB_HOST` | `${MYSQLHOST}` | Railway MySQL host reference |
| `DB_PORT` | `${MYSQLPORT}` | Railway MySQL port reference |
| `DB_DATABASE` | `${MYSQLDATABASE}` | Railway MySQL database name |
| `DB_USERNAME` | `${MYSQLUSER}` | Railway MySQL user reference |
| `DB_PASSWORD` | `${MYSQLPASSWORD}` | Railway MySQL password reference |

---

## 3. Database Migration Execution

Run migrations `001_users_and_rbac.sql` through `024_security_performance_observability.sql` against your Railway MySQL database:

```bash
# Execute migration script via MySQL CLI or Railway CLI
mysql -h ${MYSQLHOST} -P ${MYSQLPORT} -u ${MYSQLUSER} -p${MYSQLPASSWORD} ${MYSQLDATABASE} < database/migrations/024_security_performance_observability.sql
```

---

## 4. Railway Health Check Configuration

Configure Railway Health Check settings:
- **Health Check Path**: `/public/health.php?type=liveness`
- **Health Check Timeout**: 10s
- **Success Status**: `200 OK`

---

## 5. Security & Operation Checklist

- [x] `.env` excluded from version control in `.gitignore`.
- [x] Debug mode disabled (`APP_DEBUG=false`).
- [x] Passwords hashed using `PASSWORD_BCRYPT` with cost 12.
- [x] CSRF protection enabled on state-changing API endpoints.
- [x] Security HTTP headers configured (`X-Frame-Options`, `X-Content-Type-Options: nosniff`).
- [x] Database query parameters parameterized to prevent SQL Injection.
- [x] Sensitive fields redacted from application logs.
